# Пыльца Алматы

Ежедневные измерения аэроаллергенов для Алматы: 247 дней наблюдений, 48 таксонов,
два сезона. Веб-приложение для людей с поллинозом и API для тех, кто хочет
считать по этим данным сам.

Открытых данных по пыльце для Казахстана не существует. Ни Google Pollen API, ни
Open-Meteo/CAMS Центральную Азию не покрывают. Эта запись — единственный источник,
и именно поэтому весь проект построен вокруг одного правила: **придуманное число
хуже пустого экрана.**

---

## Откуда данные

Волюметрическая ловушка Буркарда (тип Хёрста). Прибор непрерывно прокачивает
воздух через приёмную щель на клейкую ленту, намотанную на барабан; барабан
делает один оборот в неделю. Ленту режут на суточные отрезки, монтируют на
предметные стёкла и считают зёрна **под микроскопом вручную** — таксон за
таксоном, день за днём. Ловушку ведёт университетская лаборатория.

Запись: **28 апреля 2025 — 6 августа 2026**, 247 дней с измерениями, 48 таксонов
(43 пыльцевых и 5 типов грибных спор).

Пропуски в записи — реальные: в эти дни прибор не работал.

```
2025-06-02 … 2025-06-29     28 дней
2025-09-01 … 2025-09-28     28 дней
2025-11-17 … 2026-03-25    129 дней   (зимний перерыв)
2026-06-01 … 2026-06-30     30 дней
2026-07-09 … 2026-07-12      4 дня
```

**Пропуск — это не ноль.** Ноль означает «посчитали, не нашли»; пропуск означает
«не считали». Это разные факты, и они по-разному выглядят везде: в ленте пропуск —
вырез со штриховкой, в календаре — просвет, на графике — заштрихованная полоса с
подписью «нет данных», а линия в этом месте разрывается. Ни одно скользящее окно
не считается через пропуск: детектор в такие дни возвращает «нельзя определить», а
не «не сработал».

## Как запустить

Зависимостей нет. `npm install` не нужен — ни одной строчки чужого кода в рантайме.

```bash
node --version          # нужен 20+
node src/server.js      # http://localhost:4000
npm test                # 73 теста
```

Порт меняется через `PORT`. Файл данных лежит в `data/almaty_trap_clean.csv`
(и `.json`); путь переопределяется через `DATASET_PATH`.

Если файла нет, сервер поднимется, но **каждый эндпоинт с данными вернёт
`503 dataset_missing`**. Мок-режима нет и не будет: цифра, которой нет в
лабораторном файле, не должна появиться на экране ни при каких условиях.

### Эндпоинты

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/meta` | границы записи, таксоны с группами и пиками, пропуски, **шкала порогов** |
| GET | `/api/day/:date` | таксоны дня, сумма пыльцы и уровень, споры, погода |
| GET | `/api/taxon/:name/season?year=&from=&to=` | дневной ряд, SPIn, границы сезона, пик |
| GET | `/api/season-state?date=&taxa=` | стадия сезона по каждому таксону |
| GET | `/api/season-state/first-ramp` | первое срабатывание детектора |
| GET | `/api/ramp-performance?taxon=&window=` | срабатывания, точность, промахи |
| GET | `/api/season-pace?as_of=&taxon=` | накопленная сумма, этот сезон против прошлого |
| POST | `/api/profile/attribute` | разбор триггеров по дневнику симптомов |
| GET | `/api/personal-index?profile=&date=` | индекс дня по личному профилю |
| GET | `/api/discriminating-days?taxon=&min_r=` | дни, разводящие коллинеарные пары |
| GET | `/api/cross-reactivity?taxa=` | **не измерение** — таблица из литературы, см. ниже |
| GET | `/api/meta` → `symptom_thresholds` | **не измерение** — пороги симптомов из литературы |

Шкала порогов отдаётся через `/api/meta`, а не зашита во фронтенд: интерфейс не
знает границ полос и не может разойтись с сервером.

## Экраны

**Сегодня.** Сумма пыльцы за последний измеренный день, вердикт по лабораторной
шкале, состав воздуха. Состав сгруппирован так, как классифицирует лаборатория:
древесные, травы. Группа с нулём тоже показана — «древесные · сегодня не
обнаружено» это измерение, и человеку с аллергией на берёзу это и есть ответ.
Рядом с таксонами, для которых опубликован порог симптомов, второе чтение из
литературы. Отдельным блоком — споры с их собственными клиническими порогами.

**Мой триггер.** Два независимых пути к личной картине:

- *Быстрый.* Отметить свои известные аллергены из двенадцати самых значимых
  таксонов записи. Два тапа — и есть индекс дня, пересчитанный под этот список,
  и полоса «ваши недели»: максимум за каждую неделю записи по выбранным
  таксонам, с обведённой текущей. Это **объявлено человеком**, а не рассчитано;
  ни весов, ни уверенности, ни ранжирования здесь нет, и с профилем модели это
  нигде не смешивается.
- *Дневник.* Отметки самочувствия по дням → логистическая регрессия → веса,
  уверенность, неразделимые группы, разделяющий день. Здесь всё как было.

Ниже — перекрёстные реакции с продуктами по верхним триггерам.

**Сезон.** Где мы сейчас против прошлого года на одном календарном отрезке, и
что было дальше в прошлом сезоне. Табло детектора нарастания с его промахом.

**Таксоны.** Вся запись, доступная поштучно. Поиск по русскому и латинскому
имени, фильтр по группе, спарклайн сезона в каждой строке, текущее значение и
стадия сезона. Разворачивается в карточку: полный график обоих сезонов с
заштрихованными пропусками, пик с датой, число измеренных и ненулевых дней,
сумма по записи, порог симптомов и перекрёстные реакции. Ниже — та же запись
помесячной сеткой 48 × 16.

Этого экрана раньше не было, и это была главная дыра: в записи 48 таксонов, а
спросить про один было нельзя.

## Что здесь делает ИИ

Немного, и это осознанно.

**Логистическая регрессия с L2 на дневнике симптомов.** Пользователь отмечает
самочувствие за конкретные дни; модель сопоставляет отметки с измеренными
концентрациями (`log1p`) и выдаёт ранжированные веса. Написана руками, 130 строк,
без библиотек.

Существенная часть — не сама модель, а то, что делается **до** неё. Таксоны, у
которых лог-корреляция ≥ 0.80, склеиваются в один признак ещё до обучения, и
группировка транзитивна. Иначе модель уверенно скажет «берёза, а не лещина» там,
где данные этого не позволяют. Группы возвращаются помеченными как неразделимые, и
интерфейс так их и называет: «Лещина, Ива и Вяз — по имеющимся измерениям их
нельзя разделить».

Дополнительно: корреляция, посчитанная по горстке дней, — не свидетельство.
*Cedrus* и *Convolvulus* ненулевые каждый по семь дней, совпадают все семь и дают
r = 1.00, что не значит ничего. Поэтому для склейки нужно ещё и **минимум 20 дней,
где оба таксона присутствовали**.

**Детектор нарастания** — не модель, а два порога: трёхдневное среднее ≥ 40 зёрен/м³
и отношение этого среднего к базовому уровню предыдущих десяти дней ≥ 1.60. Пороги
зафиксированы и не подбирались под сезон, на котором проверяются.

**Чего здесь нет:** ни LLM, ни нейросетей, ни прогноза. Ассистента в этом продукте
тоже нет.

## Что здесь не измерение

Всё остальное в `src/` считается из `data/almaty_trap_clean.csv`. Каталог
`src/knowledge/` — нет. В нём две статические таблицы, собранные по
аллергологической литературе, и он существует отдельно именно поэтому: ничто
оттуда не должно быть принято за то, что ловушка посчитала.

### Пороги появления симптомов

Рядом с измеренным счётом таксона продукт показывает второе, независимое
чтение — концентрацию, при которой в исследованиях у чувствительных людей
начинаются симптомы. Так же, как плесень уже показывала «36 из 100 · порог не
превышен».

| Таксон | Порог, зёрен/м³ | Источник |
|---|---|---|
| Artemisia (полынь) | 5–15 | de Weger et al. 2013 |
| Poaceae (злаковые) | 20–50 | Rapiejko et al. 2007 |
| Betula (берёза) | 45–100 | систематический обзор, Aerobiologia 2021 |
| Ambrosia (амброзия) | 10–50 | диапазон по нескольким исследованиям |

**Всегда диапазон, никогда одно число.** Опубликованные пороги расходятся в
несколько раз: разные популяции, разные сезоны, разные определения «начала
симптомов». Единого принятого значения не существует, и продукт его не печатает.
Диапазон идёт вместе с источником — порог без работы, из которой он взят,
читался бы как установленный факт.

**Таксон без опубликованного порога не показывает ничего.** Не прочерк, не
значение соседнего таксона, не «вероятно, как у берёзы». Из 48 таксонов записи
порог есть у четырёх.

**Лабораторная шкала не сдвигается ни на грамм.** 1–10 / 11–50 / 51–200 / >200
остаётся источником каждого уровня в продукте. Клиническое чтение лежит
вложенным объектом рядом и не участвует ни в одном расчёте: 6 августа полынь
даёт 41 зерно/м³ — это `умеренный` по лабораторной шкале **и** выше порога 5–15
по литературе. Оба утверждения верны, они отвечают на разные вопросы, и
интерфейс печатает их обоими словами в одну строку, чтобы это было видно.
Отдельный тест требует, чтобы уровень таксона с порогом и без него считался
одинаково.

### Перекрёстные реакции с продуктами


Всё остальное в `src/` считается из `data/almaty_trap_clean.csv`.
Таблица покрывает **13 таксонов записи из 48** — те, для которых пищевая
перекрёстная реактивность действительно описана. Остальные 35 не «пустые»: у них
нет записи, и продукт говорит именно это.

Границу держат три правила, и они проверяются кодом, а не намерением:

1. Модуль ничего не импортирует из данных и не импортируется ничем, что считает
   измеренную величину.
2. Ответ несёт `measured: false` и `source_kind: 'literature'` на верхнем уровне,
   а не в сноске.
3. Таксон, которого нет в таблице, возвращает **явное «нет установленных
   данных»** с причиной. Никогда — пустой список: пустой список читается как
   «перекрёстных реакций не существует», а такого утверждения эта таблица
   сделать не может.

В интерфейсе блок отделён пунктирной рамкой и подписью «Из литературы, не из
измерений» — до того, как человек прочтёт список.

**Записи неравноценны, и это видно.** Каждая помечена силой доказательств:
`established` — названный синдром с названным белком (полынь — сельдерей,
Art v 1/Art v 3); `limited` — отдельные наблюдения или перенос с родственного
вида. Строка с `limited` несёт пометку «ограниченные данные» рядом с названием
таксона и объяснение, чем именно база ограничена. Пример: связь коноплёвых с
персиком описана для конопли, а ловушка считает семейство целиком, в котором
присутствует и хмель — этот перенос назван допущением прямо в тексте. Тест
требует, чтобы каждая запись была помечена и чтобы `limited` объясняла причину.

**Формулировки.** Блок описывает, но не ставит диагноз и не назначает диету.
Он говорит «при аллергии на этот таксон возможна перекрёстная реакция», а не
«у вас аллергия»; заканчивается «есть смысл обсудить с аллергологом», а не
«избегайте». Когда уверенность профиля низкая, блок дополнительно говорит, что
показан для триггеров, определённых по короткому дневнику.

Источники записей: Thermo Fisher Allergen Encyclopedia (w6), JACI 2024 «Role of
Api g 7 in mugwort pollen-related celery allergy», Allergy 2025 «Art v 1 and
Amb a 4 Co-Sensitization». Запись без источника помечается отдельной строкой.

## Ограничения

Читать до того, как делать выводы.

**Прогноза на завтра нет — и это решение, а не недоделка.**
Наивная персистентность («завтра как сегодня») на этой записи даёт MAE
**20,1 зерна/м³** по 241 паре соседних измеренных дней и **угадывает полосу уровня
в 76% случаев**; предсказание среднего по записи даёт MAE 28,3, то есть
персистентность лучше климатологии всего на 29%. Порог, который должна была бы
превзойти любая модель, при этом высокий, а обучающих данных — два сезона с
четырьмя крупными пропусками. Пока нет доказательства, что модель бьёт «завтра как
сегодня», прогноз в продукте был бы украшением, а не функцией.

**Плесень ни разу не достигла клинических порогов.**
Максимум *Alternaria alternata* за всю запись — 67 спор/м³ при пороге 100
(Gravesen 1979); максимум *Cladosporium herbarum* — 124 при пороге 3000. Ни одного
превышения. Споры показываются отдельным блоком, с собственными порогами, и
четырёхступенчатая шкала пыльцы к ним не применяется — это разные величины с
разными единицами. Приложение не называет уровень спор «низким» или «высоким»,
потому что для спор такой шкалы нет.

**У детектора есть известный промах: 13 июля 2025.**
За сезон 2025 (окно 1 июля — 31 октября) детектор сработал 12 раз, 11 срабатываний
подтвердились критическим днём в течение 10 дней — точность 92%. Срабатывание
13 июля не подтвердилось, и окно проверки было измерено полностью, то есть это
настоящий промах, а не следствие пропуска. Поднять порог до 45 и получить 100%
можно за минуту — но такой порог был бы подобран под единственный сезон, на
котором его же и проверяют. 92% — честная цифра.

Ещё 23 дня внутри окна детектор оценить не смог: скользящее или базовое окно
попадало на пропуск. Это не срабатывания и не отсутствие срабатываний, и они
считаются отдельно.

**Двух сезонов мало для кросс-годовой проверки.**
Запись покрывает 2025 и часть 2026. Проверить детектор или пороги «на других
годах» негде: единственный завершённый сезон — тот же, на котором они оценивались.
Сезонное окно для полыни (1 июля — 31 октября) взято из этих же данных. Любые
выводы о повторяемости — гипотезы до третьего сезона.

**SPIn — нижняя оценка.**
Интеграл сезона считается по измеренным дням окна. В окне есть пропуски, поэтому
истинный интеграл выше. Ответ API помечает это флагом `spi_is_lower_bound` и
отдаёт число неизмеренных дней.

**Сравнение сезонов требует одинаковых окон.**
В окне 2026 не хватает четырёх дней. Сравнивать 37-дневную сумму с 33-дневной
нельзя — отставание выйдет больше, чем оно есть. Продукт показывает сопоставление
по совпадающим датам (777 против 511, разница в 1,52 раза) и раскрывает, какие
именно дни исключены. Сырое сравнение (920 против 511, 1,80) API тоже отдаёт, но
помечает как переоценивающее отставание.

**Дневник симптомов живёт только в памяти вкладки.**
Ни `localStorage`, ни сервера. Перезагрузка очищает отметки. Разбор триггеров —
POST, и он намеренно не кэшируется: показать сохранённый ответ для изменившегося
дневника значило бы показать выдуманный результат.

**Погода в записи вызывает вопросы.**
Метеоданные из файлов ловушки имеют подозрительно узкий диапазон (ветер
1,3–4,4 м/с) и, вероятно, являются оценкой, а не приборным измерением. В расчётах
они не используются.

## Устройство

```
src/config.js        все константы, имеющие научный смысл
src/load.js          загрузка, валидация, сверка пропусков; бросает при отсутствии файла
src/lib/logreg.js    L2-логрегрессия, написана руками
src/knowledge/       две таблицы из литературы. Единственный код, не считающий по данным
src/domain/          пороги, окна, сезон, детектор, темп, группировка, атрибуция
src/server.js        node:http, он же раздаёт web/
web/                 интерфейс: 4 экрана, офлайн-первый, без зависимостей
web/explorer.js      экран «Таксоны»: поиск, фильтр, карточка таксона
data/                лабораторный файл. Ничего сгенерированного здесь быть не может
test/                73 теста: алгоритмы на фикстурах + приёмочные значения
ACCEPTANCE.md        контрольные величины, сверенные с файлом
DESIGN.md            решения по визуальному языку и их обоснование
DEMO.md              сценарий показа с запасными вариантами
```

Офлайн: Service Worker предкэширует оболочку, три файла шрифтов и `/api/meta`;
ответы `/api/*` кэшируются по мере обращения, `offline.html` — навигационный
фолбэк. Ответ, пришедший из кэша, помечается заголовком, и интерфейс говорит
«из кэша» вместо того, чтобы выдавать вчерашние цифры за сегодняшние.

Лицензия шрифта: Geist (SIL OFL 1.1), subset до латиницы и кириллицы.
