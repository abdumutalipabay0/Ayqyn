# Ayqyn — полный контекст проекта

Этот файл написан для ИИ-агента, который берёт проект в работу. Он описывает не
только *что* здесь есть, но и *почему именно так* — потому что почти каждое
решение здесь принято против более простой альтернативы, и без объяснения его
откатят обратно.

Читать целиком перед первой правкой. Раздел «Ловушки» — обязательно: в нём
перечислены ошибки, которые уже были совершены и стоили времени.

---

## 0. За тридцать секунд

Веб-приложение и API поверх единственной в Центральной Азии открытой записи
измерений аэроаллергенов. Ловушка Буркарда в Казахском национальном аграрном
исследовательском университете, Алматы: **247 суток измерений, 48 таксонов, два
сезона (28 апреля 2025 — 6 августа 2026)**, ручной подсчёт под микроскопом.

Продукт отвечает на один вопрос: **на что реагирует конкретный человек**.

Ноль зависимостей в рантайме. Работает офлайн. 86 тестов. MIT на код, CC BY 4.0
на данные.

Репозиторий: `https://github.com/abdumutalipabay0/Ayqyn`

## 1. Семь законов

Это не стиль и не вкусовщина. Нарушение любого из них — дефект, даже если тесты
проходят.

**1. Придуманное число хуже пустого экрана.** Ни одна величина в продукте не
может быть сгенерирована, интерполирована, экстраполирована или подставлена по
умолчанию. Нет файла данных — все эндпоинты отдают `503 dataset_missing`.
Мок-режима нет и не будет.

**2. Пропуск — это не ноль.** Ноль означает «посчитали, не нашли». Пропуск
означает «не считали». Это разные факты. В ленте пропуск — вырез со штриховкой,
в календаре — просвет, на графике — заштрихованная полоса, и линия там
**разорвана**. Ни одно скользящее окно не считается через пропуск: детектор
возвращает `undetermined`, а не `not_fired`.

**3. Каждая цифра на экране приходит из эндпоинта.** Во фронтенде не должно
быть ни одного зашитого значения данных — включая границы шкалы. `levelOf()`
читает полосы из `/api/meta`. Если шкала изменится на сервере, интерфейс не
сможет с ней разойтись.

**4. Шкала пыльцы не применяется к плесени.** Пыльца градуируется
четырёхступенчатой лабораторной шкалой. Плесень — только собственными
клиническими порогами (Gravesen 1979), и слов «низкий/высокий» для неё нет,
потому что такой шкалы для неё не существует.

**5. Литература помечается как литература.** Всё, что не измерено этой ловушкой,
несёт `measured: false` и `source_kind: 'literature'` на верхнем уровне ответа и
визуальную отбивку в интерфейсе. См. раздел 5.

**6. Копия описывает, а не предписывает.** «Возможна перекрёстная реакция»,
«есть смысл обсудить с аллергологом». Никогда: «избегайте», «у вас аллергия»,
«принимайте». Продукт не ставит диагнозов и не назначает диет.

**7. Уровень читается без цвета.** Четырёхклеточный индикатор (`.stepper`)
кодирует уровень позицией, а не только тоном. Рампа монотонна по яркости —
проверяется в ч/б.

## 2. Данные

### Происхождение

Волюметрическая ловушка Буркарда типа Хёрста. Воздух непрерывно прокачивается
через приёмную щель на клейкую ленту, намотанную на барабан; барабан делает один
оборот в неделю. Ленту режут на суточные отрезки, монтируют на стёкла, зёрна и
споры считают **вручную под микроскопом**, таксон за таксоном.

Оператор: Казахский национальный аграрный исследовательский университет, Алматы.
Данные используются с разрешения лаборатории, опубликованы под CC BY 4.0
(`DATA_LICENSE.md`).

### Форма

`data/almaty_trap_clean.csv` (предпочтителен — только он несёт `group`) и
`data/almaty_trap_clean.json`.

```
date,taxon,group,count_per_m3,temp_c,humidity_pct,wind_ms
```

- `taxon` — канонические имена вида `Artemisia (полынь)`, `Alternaria alternata`.
  Русская глосса в скобках есть не у всех. Латинская часть — ключ для
  справочных таблиц: `latinOf('Artemisia (полынь)') === 'Artemisia'`.
- `group` ∈ `древесные` | `травы` | `плесень`. `плесень` = `MOLD_GROUP`.
- Погодные колонки в расчётах **не используются**: диапазон подозрительно узкий
  (ветер 1,3–4,4 м/с), вероятно оценка, а не приборное измерение.

### Пропуски — настоящие

```
2025-06-02 … 2025-06-29     28 дней
2025-09-01 … 2025-09-28     28 дней
2025-11-17 … 2026-03-25    129 дней   (зимний перерыв)
2026-06-01 … 2026-06-30     30 дней
2026-07-09 … 2026-07-12      4 дня
```

`DECLARED_GAPS` в `config.js` служит **только сверкой**. Авторитетное
определение пропуска в рантайме — «этой даты нет в наборе»
(`src/load.js#reconcileGaps`).

## 4. API

Все ответы — JSON. Ошибки: `{ error: '...' }` со статусом 400/404, отсутствие
данных — `503 dataset_missing`.

| Метод | Путь | Что отдаёт |
|---|---|---|
| GET | `/api/meta` | границы записи, таксоны (`pollen`, `mold`, `groups`, `by_peak`), пропуски, **шкала**, `symptom_thresholds` |
| GET | `/api/day/:date` | таксоны дня, сумма пыльцы и уровень, споры, соседние измеренные дни |
| GET | `/api/taxon/:name/season?year=&from=&to=` | дневной ряд, SPIn, границы сезона, пик |
| GET | `/api/season-state?date=&taxa=` | стадия сезона по каждому таксону |
| GET | `/api/season-state/first-ramp` | первое срабатывание детектора |
| GET | `/api/ramp-performance?taxon=&window=` | срабатывания, точность, промахи |
| GET | `/api/season-pace?as_of=&taxon=` | накопленная сумма, этот сезон против прошлого |
| POST | `/api/profile/attribute` | разбор триггеров по дневнику. **Не кэшируется** |
| GET | `/api/personal-index?profile=&date=` | индекс дня по профилю `Taxon:weight,…` |
| GET | `/api/discriminating-days?taxon=&min_r=&limit=` | дни, разводящие коллинеарные пары |
| GET | `/api/cross-reactivity?taxa=` | **не измерение** — таблица из литературы |
| GET | `/api/series/pollen-total?from=&to=` | ряд суточных сумм пыльцы (для спарклайна под числом) |

**Важно про `/api/day/:date`.** Для измеренного дня возвращает `measured: true`,
`taxa` (только ненулевые), `pollen`, `mold`, и `previous_measured_date` /
`next_measured_date`. Для непромеренного — `measured: false`, `reason`
(`measurement_gap` | `outside_record`), `gap`, и **никакого `taxa`**: пустой
список читался бы как «ловушка работала и ничего не нашла».

**Важно про `attribute`.** При отказе считать возвращает `fitted: false`,
`reason_code` (`no_variation` | `insufficient_data`), `requirements`
(`min_days`, `min_per_class`) и английскую прозу `reason`. Интерфейс обязан
собирать формулировку из кода и чисел — печатать `reason` на русском экране
нельзя.

## 5. Слой знания — единственное, что не измерение

`src/knowledge/` содержит две статические таблицы, собранные по аллергологической
литературе. Каталог отдельный именно поэтому: ничто оттуда не должно быть
принято за то, что ловушка посчитала.

### `cross-reactivity.js` — перекрёстные реакции пыльца/продукты

13 записей на 48 таксонов записи. Каждая помечена силой доказательств:

- `established` — названный синдром с названным белком (полынь — сельдерей,
  Art v 1 / Art v 3);
- `limited` — отдельные наблюдения или перенос с родственного вида. Строка
  несёт пометку «ограниченные данные» **рядом с названием таксона**, а не в
  сноске, и обязана объяснять, чем именно база ограничена.

Пример честного `limited`: связь коноплёвых с персиком описана для конопли
(*Cannabis sativa*), а ловушка считает семейство целиком, где присутствует и
хмель. Текст называет это допущением.

### `symptom-thresholds.js` — пороги появления симптомов

4 записи на 48 таксонов. **Всегда диапазон, никогда одно число** — опубликованные
пороги расходятся в несколько раз, консенсуса не существует.

| Таксон | Порог, зёрен/м³ | Источник |
|---|---|---|
| Artemisia | 5–15 | de Weger et al. 2013 |
| Poaceae | 20–50 | Rapiejko et al. 2007 |
| Betula | 45–100 | систематический обзор, Aerobiologia 2021 |
| Ambrosia | 10–50 | диапазон по нескольким исследованиям |

### Три правила границы

1. Модули **не имеют ни одного импорта**. Тест это проверяет.
2. Каждый построенный из них ответ несёт `measured: false` и
   `source_kind: 'literature'` на верхнем уровне.
3. Таксон, которого нет в таблице, возвращает **явное «нет установленных
   данных» с причиной**, никогда — пустой список. Пустой список читается как
   «перекрёстных реакций не существует», а такого утверждения таблица сделать
   не может.

**Одно отличие между модулями, оно намеренное.** `cross-reactivity.js` не
импортируется ничем, что считает измеренную величину. `symptom-thresholds.js` —
импортируется (`domain/levels.js`), потому что порог симптомов бессмыслен вдали
от счёта за день. Границу там держит другой механизм: чтение подвешено
**вложенным объектом** рядом с измерением и никогда в него не входит. `level`,
`count_per_m3` и все суммы считаются так, будто файла не существует. Отдельный
тест требует, чтобы таксон с порогом и без него получал одинаковый `level`.

## 6. Алгоритмы

### Детектор нарастания

Срабатывает, когда выполнены **оба** условия:
- (a) трёхдневное среднее ≥ **40** зёрен/м³;
- (b) отношение этого среднего к базовому уровню предыдущих **10** дней ≥ **1.60**.

`RAMP_BASELINE_ANCHOR = 'window'` — базовое окно `d-12..d-3`, **не пересекается**
с трёхдневным, иначе базовый уровень заражается тем самым подъёмом, который
детектор должен обнаружить.

Пороги зафиксированы и **не подбирались** под сезон, на котором проверяются.
Поднять порог до 45 и получить 100% можно за минуту — но такой порог был бы
подобран под единственный завершённый сезон.

Срабатывание считается подтверждённым, если в следующие **10 дней**
(`RAMP_PRECISION_HORIZON_DAYS`) был день выше **200** (`CRITICAL_ABOVE`,
именно «выше», не «≥»). Горизонт только вперёд: предупреждение после события —
не предупреждение.

### Склейка коллинеарных таксонов

**Делается до обучения, а не после.** Таксоны с лог-корреляцией ≥ `0.80`
склеиваются в один признак, группировка транзитивна (связные компоненты).

Дополнительно требуется **минимум 20 дней, где оба таксона ненулевые**
(`MIN_CO_NONZERO_DAYS`). Причина: *Cedrus* и *Convolvulus* ненулевые каждый по
семь дней, совпадают все семь и дают r = 1.00, что не значит ничего. Это
судейское решение, а не выведенное из данных.

Без этого модель уверенно скажет «берёза, а не лещина» там, где данные этого не
позволяют. Группы возвращаются помеченными `inseparable`, и интерфейс называет
их так же.

### Атрибуция триггеров

Логистическая регрессия с L2 (`λ = 1`) на `log1p(count)`, признаки
стандартизованы, 4000 итераций, шаг 0.1. День считается плохим при
`severity >= 2`.

Пороги уверенности: минимум **8** дней и **3** каждого класса, иначе весов не
возвращаем вовсе. Средняя — от 15 дней, высокая — от 30 дней и 8 каждого класса.

### SPIn — нижняя оценка

Интеграл считается по **сезонному окну**, а не по календарному году. Для полыни
это 1 июля — 31 октября (`SEASON_WINDOWS`). Суммирование целого года смешивает
два сезона: именно так 7592 (всё время, оба сезона) однажды приняли за SPIn 2025
года, равный 7023.

В окне есть пропуски, поэтому истинный интеграл выше. Ответ помечает это
флагом `spi_is_lower_bound` и отдаёт число неизмеренных дней.

### Темп сезона

Сравнивать 37-дневную сумму с 33-дневной нельзя — отставание выйдет больше, чем
оно есть. Продукт показывает сопоставление **по совпадающим датам** и раскрывает,
какие именно дни исключены. Сырое сравнение API тоже отдаёт, но помечает как
переоценивающее.

## 8. Фронтенд

### Четыре экрана

| id | Вкладка | Отвечает на |
|---|---|---|
| `today` | Сегодня | что в воздухе прямо сейчас |
| `trigger` | Мой триггер | на что реагируете именно вы |
| `season` | Сезон | где мы в сезоне полыни |
| `year` | Таксоны | все 48 растений и грибов в записи |

`id` вкладки «Таксоны» остался `year` **намеренно** — чтобы не ломать ссылки и
историю. Экран содержит обозреватель (`#y-explorer`) и месячную сетку (`#y-grid`)
под ним; сетка переиспользует ряды, уже загруженные обозревателем.

### Каждый экран объясняет себя сам

Судьи ходят по продукту без рассказчика. Компонент `screenHead({ eyebrow,
problem, title, lede })` открывает каждый экран **проблемой**, затем что
показано и зачем. «Что дальше» — единственное действие, которым экран
заканчивается.

### «Мой триггер» — три пути внутрь

1. **Быстрый.** Отметить известные аллергены из 12 самых значимых таксонов.
   Это **объявлено человеком**, не рассчитано: ни весов, ни уверенности.
2. **Дневник.** Отметки самочувствия → регрессия → веса, уверенность,
   неразделимые группы, разделяющий день.
3. **Готовый пример.** Дневник человека, чьи плохие дни совпадают с полынью.
   Собирается **из самой записи** по правилу «день „очень плохо“, если полынь
   выше своей медианы за окно», и правило показано читателю.

Пример живёт в `S.example`, **никогда** не в `S.log`. Поэтому очистка возвращает
подлинное пустое состояние — трогать было нечего. При активном примере
`S.profile` остаётся `null`, иначе «Сегодня» посчитал бы личный индекс по чужому
дневнику. Метка `ПРИМЕР · НЕ ВАШИ ДАННЫЕ` стоит на всех четырёх порождённых
блоках. Первая собственная отметка пример снимает.

### Состояние

```js
const S = { meta, bands, view, drawn, log, logCursor, logDates, profile, example }
```

Всё в памяти вкладки. Ни `localStorage`, ни сервера. Перезагрузка очищает.

### Офлайн

Service Worker предкэширует оболочку, шрифты, иконки и `/api/meta`; ответы
`/api/*` кэшируются по мере обращения; `offline.html` — навигационный фолбэк.
Ответ из кэша помечается заголовком, интерфейс показывает бейдж «из кэша».

**`POST /api/profile/attribute` намеренно не кэшируется.** Показать сохранённый
ответ для изменившегося дневника значило бы показать выдуманный результат.
Офлайн этот блок честно говорит «нужна сеть».

## 9. Дизайн-система

Полностью в `web/tokens.css`, обоснования в `DESIGN.md`.

**Тёмная тема первична.** Три правила:

1. **Никогда чистый чёрный.** Подложка `#0a0c0e` — почти-чёрный с холодным
   подтоном. `#000` даёт ореол вокруг светлого текста и убивает глубину.
2. **Глубина — светлые слои, не тени.** Тень на почти-чёрном не читается. Каждая
   ступень поднимает светлоту примерно на 4 пункта: `--bg` → `--surface` →
   `--surface-2`. Единственная тень в системе — на нижней панели.
3. **Один акцент, и он не заливает блоки.** Приглушённый янтарь на фокусе,
   ссылках, знаке дельты и метке «сейчас». Главное действие — нейтральный
   светлый блок (`--action`), потому что янтарь одновременно является шкалой
   опасности, и залитая янтарём кнопка читается как «критический».

Текст `#e1e3e5`, не белый. Весь текст ≥ 4.5:1. Шрифт — переменный Geist
(ось 100–900), вес ограничен **590**, 700+ не бывает. Трекинг отрицательный на
крупном, слегка положительный на тексте.

Рампа уровня — порядковая, один тон, монотонная светлота, ΔL ≥ 0.06. В тёмной
теме **анкер перевёрнут**: уровень 1 ближе всего к поверхности, уровень 4 самый
светлый. Иначе «низкий» бьёт в глаз сильнее «критического» и опасность читается
задом наперёд.

**Проверять валидатором, а не глазом:**

```
node <skill>/dataviz/scripts/validate_palette.js "#614932,#8c674a,#bd8a6b,#f2b497" \
  --mode dark --surface "#0a0c0e" --ordinal
```

Обе рампы дают ALL CHECKS PASS.

## 10. Ловушки — уже наступали, не наступать снова

**`el('svg', …)` не создаёт SVG.** `document.createElement('svg')` в
HTML-документе даёт `HTMLUnknownElement`. Узлы будут в DOM, будут иметь ширину и
**не нарисуют ничего**. Только `createElementNS`. Спарклайны так молча не
работали.

**Параметр нельзя называть `valueOf`.** Значение по умолчанию при
деструктуризации не сработает никогда: любой объект наследует
`Object.prototype.valueOf`, поиск успешен, дефолт пропускается. То же касается
`toString`, `constructor`.

**`requestAnimationFrame` заморожен в фоновой вкладке.** График, запланированный
через rAF, не появится, если пользователь переключился и вернулся. Рисовать
синхронно с запасной шириной + `ResizeObserver`.

**Pillow не умеет многокадровый ICO через `append_images`.** Это идея из
GIF/TIFF; плагин молча оставит один кадр, и файл будет заявлять четыре размера,
содержа один. Контейнер собран вручную в `tools/make-icons.py`.

**`*.png` в `.gitignore` съедает иконки.** Правило написано для скриншотов.
Нужны исключения на `web/apple-touch-icon.png` и `web/favicon-32.png`.

**Специфичность CSS: `#id` бьёт `.class[hidden]`.** `#view-trigger { display:
grid }` перебивал `.view[hidden] { display: none }`, и скрытые экраны
протекали. Решение: `!important` на `.view[hidden]` + селекторы
`:not([hidden])`. Селекторы в разных медиаблоках должны совпадать по
специфичности, иначе более ранний блок выиграет.

**Антидребезг оставлял противоречие.** Быстрые тапы откладывали расчёт, и панель
показывала «Профиля пока нет · Отметить первый день» рядом со счётчиком
«Отмечено дней: 23». Пустое состояние снимается на первой же отметке.

**Перерисовка контейнера съедает быстрый второй тап.** Перестройка всего блока
на каждый тап уничтожает узел, по которому пользователь целится, и теряет фокус
с клавиатуры. Перерисовывать только результат.

**Спарклайны нельзя нормировать каждый к своему максимуму.** Пик 5 и пик 1662
дадут одинаковый силуэт. Общий масштаб обязателен; при разбросе в три порядка —
логарифмический, и это должно быть **написано над списком**, а не под ним.

**Русские падежи.** Имена таксонов приходят из API несклоняемыми. Нельзя писать
«для {taxon}» или «при аллергии на {taxon}». Строить фразу так, чтобы имя
осталось в именительном: «В таблице нет данных для этих таксонов: X, Y» или
«X — при аллергии на этот таксон…». Числительные согласовывать через `plural()`.

**Английская проза из API на русском экране.** `attribute()` возвращает
`reason` по-английски для читателя API. Интерфейс обязан собирать текст из
`reason_code` и `requirements`.

**Две липкие области с `top: 0` наезжают друг на друга.** Строка свежести и
панель навигации должны лежать в одной обёртке `.stickytop`.

**`web/sw.js` VERSION.** Любая правка в `web/` требует поднять версию, иначе
браузер будет отдавать старую сборку. При проверке — снимать регистрацию и
чистить кэши.

## 11. Чего здесь нет — и это решения, а не недоделки

**Прогноза на завтра.** Наивная персистентность даёт MAE 20,1 и угадывает полосу
уровня в 76 % случаев на 241 паре соседних измеренных дней; климатология — 28,3.
Порог, который должна превзойти модель, высокий, а обучающих данных два сезона с
четырьмя крупными пропусками. **Модель, создающая ложную уверенность, хуже, чем
её отсутствие.**

**Карты и интерполяции по городу.** Ловушка одна. Рисовать поле по одной точке —
враньё.

**Тревог по плесени.** Измеряем, но клинических порогов она ни разу не достигла.

**Межгодовых заявлений.** Сезонов два; единственный завершённый — тот же, на
котором оценивались пороги.

**LLM, нейросетей, ассистента.** Атрибуция — логистическая регрессия на 138
строк.

**Уведомлений.** Требуют инфраструктуры, которой в офлайн-первом продукте без
зависимостей нет.

## 12. Как проверять

```bash
node --version          # нужен 20+
node src/server.js      # http://localhost:4000, порт через PORT
npm test                # 86 тестов
```

Полный набор проверок перед тем, как считать правку готовой:

1. **Тесты** — `npm test`, все до одного.
2. **Офлайн** — прогреть все четыре экрана, погасить процесс
   (`curl → 000`), перезагрузить: страница обязана отрисоваться из кэша.
3. **Оттенки серого** — `document.documentElement.style.filter='grayscale(1)'`,
   уровень должен читаться по индикатору и слову.
4. **Ширины 390 и 1280.** Ресайз окна расширением **не работает** — вьюпорт не
   меняется. Использовать iframe нужной ширины: в нём медиазапросы считаются от
   его размера. Искать горизонтальное переполнение и узлы, вылезшие за
   контейнер.
5. **Контраст** — резолвить вычисленные цвета через канвас: Chrome возвращает
   `oklch(...)`, и наивный парсер прочитает эти числа как RGB.
6. **Палитра** — `validate_palette.js --ordinal` в обеих темах.
7. **Копия** — grep по запрещённым словам: «избегай», «исключит», «не ешь»,
   «откажит», «у вас аллерг», «принимайте», «диагноз».
